# v0.8 实际漫画布局校样

本轮开发A04/A05/A06，并补A03的具体案例。GPT Image 2.5直接生成漫画的验证在独立制作分支；本轮复用已有画格，不把布局重排说成模型生图能力。

## 实际剧情与两个方案

采用v0.7《最后一张票》中文第一页四格：带票抵达剧院→进门咳嗽→幽灵等待结尾→认出母亲唱过的曲子。真实字体、声音标记、思想接耳语与原画随画格一起等比放置，格内内容不改。它是连续故事的开篇片段，不冒称完整新作或全书布局已通过。

- **整页网格600×900**：四格同时可被扫视，建立人物关系；不声称能把幽灵藏到读者读完第二格。
- **分段阅读600×3840**：抵达、入内后才滚到幽灵；完整保留各格信息与文字。显示字号随画格等比放大，适合在手机宽度上逐段观看，但完整竖格较长。这里验证的是布局与信息暴露差异，没有读者实验，也没有把格间距换算成阅读秒数。

全图及实际尺寸已查看，原有标题、门牌、咳嗽、心灵声、思想与耳语均可见；脸、票据、钢琴和声源相对位置保持。没有为适配槽位扭曲人物，也没有截词或补写台词。两个方案各有目的，不自动给“更好漫画”结论。

## 故障与修正

故障版把幽灵格缩小并移到反应格右侧。实看时出现“先认出曲子，后读幽灵发言”的倒置，幽灵对白也明显变小。工具报 `layout_order_conflict` 与 `layout_text_small`（约15.01px，低于该页18px阈值）。诊断页保留，不作为成品。

首版检查器还把等比居中后不到1px的边缘错位误报为分组歧义。加入保守对齐容差及回归：1px或较短格高的1%，取较大值，仅过滤微小边缘差异；这是本地启发式，不是行业规则。最终两个布局0问题。

## 程序范围

`layout-proof` 接收冻结源页、真实背景/字体和带源页哈希的方案。每格必须按原叙事顺序列出且恰好一次，附叙事变化说明。槽位只等比容纳完整源格，不拉伸、不任意裁图。实际摆位与槽位都会记录。

检查包括槽位越界、画格相压、明显几何倒序、需要复核的交错分组、缩放后字级、源格边界裁掉的字面/声线标记/气泡框/尾尖。跨格壳会报错，不静默裁成另一种效果。任意曲线整段/描边外扩的精确裁切、复杂插格、破框、跨页和自动图像理解仍未覆盖。源页原有检查照常保留。

SVG保留可编辑Unicode、源画稿和统一变换；PNG从矢量直接渲染。输出同时保存源页、方案、每方案报告和同宽HTML对照；异常清理暂存，检查问题保留诊断稿。图形与文字不各走一条变换链。原稿和背景始终不覆盖。

## 证据与边界

新增10项测试覆盖完整映射、等比字级、裁字/裁壳、倒序/重叠、小字、对齐误报、真实栅格画面及字体、陈旧输入和原文件不变。完整本地185项测试通过（Chromium启用，92.68秒）；安装/发布核验见项目交付记录。

NAS `v08/diagnostic/` 是保留的故障稿；`layout-first/`含误报警告，图像仍供追溯；最终 `layout-final/index.html`、`page/reading.png`、`sequence/reading.png`。工作索引和45模块台账更新A03/A04/A05/A06/E05，全部模块用户验收仍未记录；没有新模型训练。

沿用已保存的布局Skill和两站图文留位/读序原则，本轮没有新增网站正文、图示或视频研究完成声明。A04只是已有画格的真实内容方案比较，不是已实现自由绘画缩略草图画板。
